# 10 · 模型调用收束与盯盘降级

Status: 第一刀已落；监控池收窄待主策略

## 已完成（2026-09-14）

**一、让模型下结论的调用全部关到默认关**

- `etfwatch.agentConfirmBuy` 默认值改为 false，并通过接口把库里那个显式的 `true` 也关掉
  （只改代码默认值不生效——库里有显式值会覆盖它）。关掉后走已存在的纯规则分支。
- `watch` 新增 `agentFinalVerdict` 开关，默认 false。关掉时 dispatcher 只落一条可核对
  记录（标的 + 方向 + 触发价 + 依据），不再调模型终审。设置面板里可切回。

依据不是省钱，是实测无效：判卷机在 915 条可判买点上给出「尚无证据显示优于随机」，
其中被模型标为「建仓」的那批事后表现还差于它标为「放弃」的。

**二、把规矩变成会变红的检查**

`llmPurposes.selfcheck.ts`：扫全仓运行时代码里的每个 `purpose`，与清单比对。
源码里出现未登记的用途就红，想加新调用点必须先写清它属于哪一类、产出进哪条链、由谁判分。
登记了却已从源码消失的也要清掉——留着会让人以为还有这条链路。

它不替人判断某个用途该不该存在，只**逼出声明**。靠记性管不住二十多个调用点。

**首次运行的结果本身就是一条发现**：

| 类别 | 个数 |
| --- | --- |
| 使用者主动提问 | 5 |
| 翻译（把规则结果转人话） | **0** |
| 核查（排雷，可一票否决） | **0** |
| **让模型下结论** | **14** |
| 基础设施 | 1 |

约定的职责边界是「模型只做翻译、核查、答追问」，而实际是 14 个下结论、0 个翻译 0 个核查——
**完全相反**。这 14 个目前全部落在默认关闭的开关后面，但「默认关」不等于「不该存在」；
真要收到 3 到 4 个，得逐个改造成翻译或核查形态，那是后续的事。

**三、一键跑全部自检**

`runSelfchecks.ts` + `pnpm check`。此前 50 多个自检只有 glossary 挂了 npm script，
其余要手敲路径、CI 也不跑，于是「产出价格数量方向的代码必须有检查钉着」这条规矩
实际靠有人记得去跑。现状：**51 个通过、1 个跳过**（kol 要真连小红书，属环境核对，
已在跳过清单里写明原因）。

只收 `*.selfcheck.ts`；`*.probe.ts` 与 `*.livecheck.ts` 不收——前者只打印不断言，
后者依赖外部服务，放进来会让这条命令因环境问题常态变红，红得太容易就没人看了。

## 待办

**监控池收窄**：现在仍是「真实持仓 + 跟踪池 + 额外代码」的大杂烩。

## 白名单

收束不是新决策，是操作台职责边界的直接推论：**规则出结论，模型只做不改变结论的事。**

按这条尺子量，`watch-research`、`market-review`、`research`、`analyze`、`decision` 做的都是「让模型给结论」，全部不合规。不是因为费钱所以要砍，是因为它们违反了职责边界；费钱只是这个错误的代价。

**只有三类用途允许调用模型：**

1. 把规则算出的结果翻译成人话
2. 核查有无重大消息面异常（可一票否决，不可发起买入）
3. 回答使用者主动提出的追问

现有 15 个用途砍完大约剩 3 到 4 个。

不额外设置额度闸门——翻译和事实核查的上下文天然就小，1.5 万 token 那种规模是「让模型从头研判」才需要的，而那类用途本来就要下线。

所有调用必须经统一门面 `gateway.call()`，见 `.cursor/skills/stock-agent-llm-gateway/`。

## 盯盘从建议来源降级为执行触发器

**主策略决定买什么，盯盘只回答什么时候到点。**

1. **只对合格标的工作。** 监控池不再是「真实持仓 + 跟踪池 + 额外代码」的大杂烩，只有两类：主策略当前认可的候选（等入场）、当前真实持仓（等退出）。
2. **输出改成可核对的记录**，不再是建议：标的、方向、触发价、到期日、依据。到期自动核对加随机对照，按依据分类统计。它从一个每天花钱说话的顾问，变成一个每天攒证据的记录员。
3. **模型调用清零。** 触发判断纯规则。唯一保留的是使用者在操作台点开某只标的时的追问。
4. **`watch` 与 `weipan` 同样处理。** `watch` 降级为个股线的执行触发器，只在主策略选中的赛道内工作。`weipan` 是短线打法、使用者自己也不上仓位，先只记录不采信——照常运行、照常攒成绩单，但产出不进操作台的动作列。

## 预期体感

系统会安静很多，短期内给出的东西更少。这是对的：一个每天花一百万 token 生产没人看、也不能验证的内容的系统，安静下来不是退步。
