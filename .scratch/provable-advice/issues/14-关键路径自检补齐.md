# 14 · 关键路径自检补齐

Status: open

规矩：**凡是产出价格、数量、方向的代码，必须有一个跑得起来的检查钉着它。没有检查的，不准进建议区。**

## 现状

`backend/src/scripts/` 下有 63 个文件，约 60 个是自检 / 探针 / 实盘核对脚本。覆盖面不差，但有三个结构性问题：

1. **只有 `glossary:check` 一个 npm 入口。** 其余近 60 个脚本没有 npm script，只能手动指定路径跑。**没有一键跑全部的入口。**
2. **没有 CI 在跑它们。** `.github/workflows/` 下只有 `docker-image.yml`。
3. **没有常规测试框架**（无 vitest / jest 配置）。保护全靠这些脚本，而它们不会被自动触发。

## 要做的

**A. 一键入口。** 加一个 npm script 跑全部断言式自检，逐个报告通过 / 失败，任一失败即非零退出。区分「断言式自检」和「只打印结果的探针」——后者不算保护，不进这个入口。

**B. 补上缺失的检查。** 按关键路径逐条核对：

共 59 个脚本（48 个自检、4 个探针、7 个实盘核对）。按模块：swing 14 个、标的计划 9 个、K 线与量能 4 个、交易与纪律 4 个、其余分散。

| 关键路径 | 现有脚本 | 状态 |
| --- | --- | --- |
| 止损计算与更新 | `disciplineStop` | 有 |
| 定时调度与漏跑 | `cronSlots`、`snapshotGap` | 有 |
| 买卖触发价生成 | `symbolTradePlan`、`tradeGuard`、`symbolPlanEval` | 部分 |

| **前复权修正** | — | **缺** |
| **真实持仓同步** | — | **缺** |
| **相对强弱排名** | — | **缺**（`rotationSwap` 管的是换手判定，不覆盖排名本身） |

**C. 已确认仍存在的错误：模拟层位与建议仓位不一致**

机制已查清：

- `heldPct`（`etfwatch/engine.ts:341`）是已建各层按配置比例求和，护栏用它算剩余仓位（`confirm.ts:290-295`）
- `sizePct`（`confidence.ts:256`）取模型输出，缺省回退到本层目标比例，写进指令并推送展示（`dispatcher.ts:97`）
- 确认建仓后 `applyMutation`（`engine.ts:281-296`）**只增删层号，完全不读 `sizePct`**，下一轮 `heldPct` 按层配置全额计入

**后果**：模型说买 10%、而第三层配置是 40% 时，推送给使用者的是 10%，模拟层位按 40% 记账。关闭模型时 `sizePct` 等于本层目标，两者才一致。

按 `issues/10` 盯盘的模型调用要清零，这个不一致会顺带消失——但**记账口径必须显式定义**，不能靠"模型不参与了所以碰巧对上"。

**D. 另两个待复核的已知错误**

1. **仓位单位。** `backend/src/plan/` 里给模型的 `holdRate` / `positionRate` 是否仍存在「小数直接拼百分号」——0.3（代表 30%）被渲染成 `0.3%`。
2. **未知持仓当空仓。** 持仓读取失败时，代码或提示词是否仍按「未持有」处理。**未知持仓不是空仓**，读不到就不该生成精确数量。

确认仍存在后，先写一个会失败的最小检查，再改生产逻辑。

## 可靠性风险排序

工作按此优先，理由见 `总纲.md` 第六节：

1. **不声不响地失败**（最危险，三个月计划空窗是实证）
2. **给错数**
3. **自相矛盾**
4. **崩溃**（显性，坏了就修）

## 还需要一轮扫描

以下审计本轮未能完成，需要补：

- **吞异常**：`catch` 块里不重新抛出也不上报、直接返回默认值的地方，范围限 etfwatch / plan / decision / positions。
- **数据新鲜度未校验**：生成今天的动作时，取用的行情、持仓、信号有没有校验日期是当前交易日；缓存命中后是否校验缓存的数据日期。
- **缺失数据按默认值处理**：已知线索是 `screener/scorer.ts` 可能存在「指标缺失按 50 分计」，会改变排名。
- **警告不阻断**：产生了数据不全的标记但仍输出精确价格或仓位的地方。
- **重复实现**：止损、仓位基数、相对强弱窗口、前复权、MACD / ATR 等基础指标、以及「板块」的定义，在多个模块里是否各算各的、口径是否一致。不一致会导致不同页面给出互相矛盾的数字。
