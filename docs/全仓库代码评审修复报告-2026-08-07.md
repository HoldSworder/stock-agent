# 全仓库代码评审修复报告（2026-08-07）

本轮不是针对某个功能的迭代，而是对**全部代码模块**做了一次 defect-first 评审并修复。评审覆盖后端约 7.5 万行、前端约 4 万行、shared 7 千行，以及 Python sidecar 与浏览器扩展。

评审方式：OCR（open-code-review）委托模式确定范围与规则，按业务域拆成 11 个只读评审 agent 并行审，所有结论回源码逐条核实后，再拆成 7 个修复 agent 并行落地；关键取舍经 GPT-5.6 Sol 跨模型交叉评审两轮收敛后才动手。

## 一句话总览

修复了 **5 个 Critical、约 25 个 High、约 50 个 Medium** 缺陷。其中影响最大的一类不是崩溃，而是**系统在数据取不到时不报错、而是给出一个看起来正常的错误结论**——这类问题会直接污染交易决策，且从界面上完全看不出异常。

## 一、这次修的问题分四类

### 第 1 类：取不到数就补 0 / 用近似值冒充真值（最危险）

这类缺陷不会报错，而是把「没有数据」变成一个看起来合理的数字，然后喂进 AI 决策或直接展示给你。

| 修复点 | 修复前 WebUI 上你看到的 | 修复后 |
| --- | --- | --- |
| 决策快照的「近 60 日收益」 | 恒定显示 `+0.00%`（取 60 根 K 线算 60 日收益，样本差一根，直接返回 0），并原样写进 AI 决策 prompt | 取数根数提到 90 根；样本不足显示「—」，不再用 0 冒充「零涨跌」 |
| 大盘状态判定 | 全市场等权指数取不到时，用「当日上涨家数过半」冒充「站上 60 日均线」，于是随便一天上涨家数过半就可能把大盘判成**主升**并建议 60–90% 仓位 | 代理值只参与宽度评分，不再点亮主升阶段判定 |
| ETF 轮动榜 | 某只 ETF 取数失败会被判成「破位」，并配上「跌破 MA60，规避/离场」的确定性文案 | 数据不足的标的从榜单剔除并在说明里记数，不再用确定性结论掩盖缺数据 |
| 模拟盘持仓 | 行情取不到时用成本价冒充现价，浮盈显示 0，还被当作当日权益样本落库污染前向验证曲线 | 缺价不再编造盈亏，并跳过当日样本 |
| 涨停/跌停/炸板池 | 休市日显示「涨停 0 家、赚钱效应冰点」，而事实是当天没开市 | 非交易日回退取上一交易日，并透出实际取数日期 |
| 战法回测的均线/MACD/KDJ | EMA 从第 1 根就返回值（等于当根收盘价），于是预热期用垃圾值开仓；MACD 前 9 根的 `dea` 近似等于 `dif`；KDJ 用的是国际口径而非通达信口径 | 预热不足一律返回空不开仓；MACD 要求信号线稳定后才认交叉；KDJ 按国内 1/3 权重递推重写 |
| sidecar 行情字段 | 停牌、新股首日、ETF 无 PE/PB 时上游返回空串，被静默转成 `0`，于是算出 -100% 涨跌幅、PE=0 被当成「极度便宜」 | 缺失一律返回空值，由后端显式判空 |

### 第 2 类：盘中未收盘的数据被当成已收盘数据用

| 修复点 | 修复前 WebUI 上你看到的 | 修复后 |
| --- | --- | --- |
| K 线缓存兜底 | 上游回源失败时，把盘中用实时报价合成的「临时 K 线」当成完整日线返回。这根临时 bar 的最高/最低/收盘由 `max/min(昨收, 现价)` 合成、必然共线，导致「收盘位置」恒等于 1.0，于是**「突破获量能确认」这个信号被确定性伪造出来** | 非交易时段的临时 bar 在兜底出口被剔除，宁可少一根完整日线也不给假的 |
| 盘中增量写入 | K 线弹窗刷新已经拿回真实当日 OHLC，10 分钟后的盘中任务又把真实最高/最低覆盖成 `max/min(昨收, 现价)`，当日振幅与 ATR 被系统性低估 | 保留真实开高低、用新报价更新收盘并合并极值 |
| 经典枢轴点位 | 用「当日还在动的那根 K 线」算枢轴，导致盘中每次刷新支撑压力位都在漂移（枢轴的定义本是用上一时段推算本时段） | 改用最新一根**已收盘**的 bar，盘中不再漂 |
| 涨停价候选 | 收盘重算（15:30）时基准取错一天，算出的是**今天**的涨停价而不是下一交易日的，偏差可达一整个涨跌幅 | 按 K 线是否收完选择基准根 |
| 指数 K 线每周被清空 | 每周全量重刷时按 6 位代码删除旧数据，但指数与个股代码会撞车（如上证指数与平安银行都是 `000001`），导致指数历史每周六被整段删掉 | 刷新与清理都按「代码 + 市场标识」配对，指数正常参与刷新 |

## 三、量化研究口径（影响回测可信度）

| 问题 | 修复前 | 修复后 |
| --- | --- | --- |
| **Supertrend 离场从未触发** | 判定式化简后等价于 `0 < -(mult+1)×ATR`，而 ATR 恒非负——这道离场规则**一次都没生效过**，写了它的策略实际只靠均线兜底，历史回测系统性偏乐观 | 按标准 ATR 上下轨状态机重写（真实 TR、只收紧不放宽的轨道、与前一根最终轨道比较翻向），并补 6 个可手算的场景断言 |
| **零成本零滑点回测** | 模式跟踪与系统重跑全程不扣任何费用，调仓频繁的策略收益被系统性高估，而这些数字又落库并在列表页排序做横向对比 | 引入成本配置并在两条路径都扣费；**ETF 不计印花税**（不套用股票默认档） |
| 站内跟踪与回测留档不同源 | 站内跟踪用数据库里的 53 只 ETF 池，而 `mode/` 下留档的 python 基准用研究脚本内置的 55 只池（多通信嘉实、化工富国两只）。通信嘉实会拉低通信主题分，正是它触发了基准里 2025-09-16 那笔换仓——于是站内少一笔换仓、此后整体错位。这个自检**长期红着被当成「遗留无关失败」** | 已实测：用基准那份 55 只池在站内重放，**与 python 留档逐笔零差异（27/27）**，证明因子链与回放逻辑移植本身是正确的。自检固定用研究池验证移植正确性；生产跟踪保留用户实际的池子不动，但会标注「与回测留档不同源、不可直接对比」，并阻止与研究基准混入同一晋级判断 |
| 晋级门归因错位 | 当日收益按**当日新选出**的持仓分摊，而这笔收益实际是**前一日持仓**赚的，于是当日刚买入的标的背上买入前的涨跌、当日卖出的标的丢掉最后一段收益 | 先把收益归给上一日持仓，再关旧回合、开新回合 |
| 回测幸存者偏差 | 取数失败的标的被剔除后照常出组合指标，而这类失败集中在退市、长期停牌、流动性差的标的上，剔除方向系统性偏乐观；等权曲线还让无数据标的以「权益 1」冒充持币，稀释早期涨跌与回撤 | 输出覆盖率并在偏低时警告；等权分母改为当日实际有数据的标的数 |
| 战法参数无校验 | 规则参数不做运行时校验，`days = 0` 会让「创新高」条件恒成立，回测产出一条看似正常实则每日开仓的曲线 | 加运行时校验，非法值拒绝 |
| 模拟盘并发超买 | 现金校验读的是网络请求之前的快照，定时调仓与盯盘自动卖出并发时后写覆盖先写，**账户现金凭空增加** | 报价返回后开事务，事务内重新读取现金与持仓再校验 |

## 四、其他数据正确性

- **时区**：财联社降级快讯源、研报窗口、驾驶舱「今日新增」、告警「今日 N 条」此前都用容器本地时区（UTC）解释无时区文本或截取日期，导致时间轴偏 8 小时、盘前 00:00–08:00 的内容不计入今日。已统一为上海口径。
- **公告抓取**：任何一页失败（含第一页）都静默返回已拉到的部分，第一页失败即返回空集，AI 会据此断言「今日无重大公告」。现在首页失败直接报错，后续页失败会标记「不完整」，研报页显示横幅、AI 上下文里也如实说明。
- **种子任务复活**：每次启动都重建全部种子任务，你删掉的自动 LLM 任务重启后复活且自动启用，持续烧 token。现在只补新增种子，影子任务默认关闭。
- **sidecar 崩溃与假死**：龙虎榜对「无上榜记录」这一最常见情形必崩；东财限流状态无锁导致并发下限流完全失效、正好命中封禁条件；每个请求都重建通达信客户端、最坏单请求阻塞约 260 秒并打满线程池导致整体假死。均已修复。
- **ETF 判定**：`5xxxx` 正则少一位导致 6 位沪市 ETF（512880/588000 等）被当个股，套用 8% 止损而非 ETF 的 12%，单票上限也被收紧。
- **涨跌停幅度**：科创板 688 按 10% 推算（实际 20%）、ST 未按 5% 处理，导致 688 涨到 10% 附近误报炸板、真正临近涨停时反而不报。

## 四点五、E2E 回归中新发现并修复的缺陷

界面回归时又挖出两个接口测不出来的问题，都已修掉。

**指数类标的的日线缓存此前完全失效。** 前端按 `secid` 取 K 线时不传 `code`（`api.ts` 里是 `secid ? { secid } : { code }`），后端 `code` 取到空字符串就直接写进缓存。而日线缓存的身份是 `(code, secid)` 这一对，于是写进去的是一批 `code` 为空的行——下次按 `code=000300` 去读永远读不回来，缓存对指数等于不存在，每次都要全量回源；同时每轮预热都会拿这些空代码去取数、必然失败。你在数据源页看到的「⚠ 121 只失败」里就混着它们，真正需要关注的失败被这批噪音淹掉。

修法是后端在只拿到 `secid` 时从中反解出代码补齐（`1.000300` → `000300`），并在列举已缓存标的时挡掉非法代码行。真实数据库里已积累的 311 行空代码脏数据已清理。修复后实测：只传 `secid` 取沪深300 日 K，落库身份为 `code=000300, secid=1.000300`，空代码行不再产生。

**后端保活的冷启动窗口过短。** supervisor 只给冷启动 20 秒，而后端启动要跑 schema 迁移、种子灌入和首轮行情预热，实测就在 20 秒临界线上。超时后下一轮循环的清理逻辑会把**正在启动的后端**杀掉，陷入「起一半就被杀」的无限重启，日志里只剩 keepalive 行、看不到任何后端输出。改为以「子进程是否还活着」为判据、上限 60 秒兜底。

另外更新了 `.env.example` 与 `.env` 里关于 `CORS_ORIGINS` 的说明——原注释写「留空则反射任意来源」，与收紧后的行为已不一致，容易误导成「本地开发不用管」。

## 四点六、第二轮复审：修复自己引入的缺陷

第一轮修完后又跑了一轮 OCR 复审，评审对象换成**这批修复本身**（138 个改动文件）。结果值得记录：**上一轮修复引入了 8 个 Critical、13 个 High**。大规模并行修复本身就是新缺陷的来源，这一轮复审的价值不比第一轮低。

其中三条属于「修复比原缺陷更危险」，都已修正：

**指数 K 线会取回另一只标的的数据。** 为解决「缓存写出空代码行」，我在 `/api/kline` 里从 `secid` 反解出代码补齐。但 K 线源里 `astockdata`(mootdx) 完全忽略 `secid`、只把代码当 symbol，而它在分钟链里排第一——补齐后上证指数 `1.000001` 会以 `symbol=000001` 命中它，取回**平安银行**的 K 线并长期写进缓存。补齐前代码为空恰好起了「让该源报错跳过、交给认 secid 的腾讯/东财」的作用。改为：补齐只作用于缓存身份，绝不进取数链。

**浏览器扩展的自选股面板被整块打死。** 给 `BRIDGE_SECRET` 降权时只看到它被用于推凭据，实际扩展用同一把密钥调了自选列表、增删、分组、K线、分时、代码联想六类接口。「bridge 密钥读设置返回 401」这条我验证过的安全边界，同时就是这条可用性回归。改为按明确白名单放行那几个只读/自选接口，并同步放开它们的 CORS（扩展发的是 `chrome-extension://` 源，不放开浏览器会在 CORS 阶段就拦掉响应体）。

**成交量取 max 形成棘轮。** 盘中合并 bar 时把成交额和成交量都取了 max，但成交量不是上游给的累计值，而是 `成交额 ÷ 现价 ÷ 每手股数` 估算出来的——分母随价格变，价格上行时同一份成交额会推出更小的手数。取 max 会把当日量能永久钉在「价格最低那一刻算出的最大估值」上，反而抬高量比与放量确认，正是本轮想保护的那个信号。改为与合并后的成交额同源重算。

其余较重要的几条：

- **缓存命中判据放宽过度**：只记「上次拿到多少根」不记「上次要了多少根」，于是「要 260 拿到 260」被误判成「历史只有 260 根」，之后 500 根的请求永久命中 260 行的短缓存**静默返回被截断的历史**，而 MA120、回测这类消费方拿到短序列不报错、只是算出偏短窗口的指标。
- **临时 bar 剔除漏了命中路径**：只做在回源失败的兜底路径上，收盘回填失败时当日行停在临时态，次日开盘前缓存命中路径照样把那根合成的假 bar 交出去。
- **通达信客户端并发串包**：改成模块级缓存后被线程池多个线程共用，而调用不在锁内，pytdx 的有状态 TCP 协议交错读写会**静默返回另一只标的的 K 线**（原先每次新建客户端反而是安全的）。
- **防守闸门被静默关掉**：`save_today_plan` 的运行时归一里，仓位百分比缺失会让整份大盘研判归零，而研判为空时下游时机档位兜底成「均衡」，于是看空时本该触发的防守档「禁新开多」硬纪律失效。
- **ETF 死信队列饥饿**：收紧重投白名单后，「观察」留痕会把队列的 20 个名额占满，真正推送失败的建仓/硬止损再也进不了候选（过滤发生在取数之后）。
- **换代当天大量标的「无计划」**：候选模型升版时把全部生效计划一次性打成过期，但每轮只重建 8 只，跟踪 N 只标的需要 ⌈N/8⌉ 个交易日才能恢复。
- **组合回撤出现凭空的假跳**：等权分母改成「当日有数据的标的数」后，每有一只标的首次出现数据，组合权益就向 1 跳一次，这个假跳直接进最大回撤——原来是低估波动（连续但被稀释），改完变成造出不存在的回撤（不连续）。
- **晋级门样本被结构性截断**：口径哈希建在「今天取数成功的池子」上，任意一只 ETF 一次瞬时超时就换哈希，而晋级门只回溯到第一次口径变更为止，于是样本数在反复截断下永远攒不满。
