# 0002 · 规则定版后至少一个完整季度不改参数

日期：2026-09-14
状态：已采纳

## 背景

系统需要一份使用者自己会相信的成绩记录，才可能被真正执行。成绩记录有两种来源：

- **回测**：可以无限次重跑。改个参数、换个条件，立刻得到一条新曲线。这是它的用处，也是它的病——人会不自觉地一直跑到曲线好看为止，而好看的那组参数是被历史数据挑出来的，不是被市场验证的。
- **前向记录**：不能重跑。系统在某天发出的建议就是那一条，产生于当时的代码、当时的数据、看不到未来的条件下。证据力高一个数量级。

要让前向记录成立，必须给每套规则一个版本号，任何参数或条件的改动都算新版本，旧版本的记录不能和新版本混着算。否则「不能重跑」这个性质就不存在了，前向记录退化成另一种可以调到好看的回测。

## 决策

**主策略定版之后，至少冻结一个完整季度不改参数。** 改动即产生新版本，计数从头开始。

攒记录期间看到回撤也不换。

## 备选方案与不选的理由

**不冻结，承认前向记录只是流水账。** 那么系统就只剩回测这一种证据，而回测无法回答「它会不会在下跌里让我扛单」——这恰恰是使用者不敢投真钱的根本原因。

**缩短冻结期到一个月。** 五十几笔交易的策略，一个月只有几笔，样本量不足以说明任何事。

## 后果

- 这条的代价不是技术上的，是心理上的：每次看到回测榜第一名不是当前主策略，都会想换；而一换，记录就要清零重算。
- 第一次要付这个代价的场合已经明确：选定 theme-first（回测排第六）而不是 breadth-confirmed（排第一）上岗之后。
- `backend/src/swing/ruleVersion.ts` 已实现参数哈希升版与旧版标记，机制不用新造。
